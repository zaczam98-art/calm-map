# 무던한 지도 (Calm Map)

발달장애 아동 가족이 외출 전에 "이 장소는 오늘 몇 시가 무던한가"를 보는 AI 감각부하 지도입니다. 2026 AI 라이프 아이디어 챌린지 수상 후보작 "무던한 지도(Calm Map)"를 기반으로 한 AI 라이프 솔루션 챌린지 출품작입니다.

- 테스트 URL: https://zaczam98-art.github.io/calm-map/
- 서버 없이 GitHub Pages와 GitHub Actions만으로 동작합니다.

"아이가 힘들어하는 것이 있나요?"를 묻고, 사이렌·경적·알람, 사람이 많은 곳, 안내방송·큰 음악, 공사·기계 소리, 그냥 큰 소리 중에서 고르면 해당 민감도를 예민(1.5)으로 두고 맞춤을 켭니다. 서울시 실제 자료가 있으면 지수가 가장 많이 달라지는 장소를 예로 "맞춤을 끄면 N점, 켜면 M점"으로 미리 보여 주고, 예시를 보여 줄 수 없을 때(소리 항목만 고름, 계산한 예시가 없음, 데모 데이터로 연 화면)는 상황에 맞는 문장으로 알립니다. 아무것도 고르지 않으면 "맞춤 없이 둘러보기" 단추 하나만 보이고, 하나 이상 고르면 "N개 적용하기"가 함께 보입니다. 닫으면 안내를 봤다는 표시(`calmmap.intro.v1`)만 기기에 남기고, 지도 위 안내 막대는 지도에서 처음 한 번 따로 띄웁니다. | `src/components/Onboarding.tsx` |

## 실행

```bash
npm install
npm run dev        # http://localhost:5173 (공개 자료 주소가 없으면 데모 데이터로 동작)
npm run build
```

공개 자료로 개발 화면을 보려면 `VITE_PUBLIC_SNAPSHOT_URL`에 data 브랜치의 `snapshot.json` 주소를 넣고 실행합니다.

## 자료 수집 (GitHub Actions)

서울 열린데이터광장 API는 8088 포트만 열려 있어 브라우저나 서버리스 함수에서 직접 부르기 어렵습니다. `.github/workflows/collect.yml`의 수집 작업 하나가 매시 6분에 한 바퀴(`scripts/cycle.sh`)를 돌고, 5시간 45분이 지나면 다음 작업을 스스로 실행해 이어 갑니다. 2시간마다 도는 예약 실행은 이 사슬이 끊겼을 때의 예비입니다(GitHub의 예약 실행은 자주 늦어지거나 빠집니다). `scripts/collect_seoul.py`는 직전 수집 후 50분이 지나지 않았으면 건너뛰어 장소당 호출을 약 1시간에 한 번으로 묶습니다(121곳이면 하루 약 2,900~3,400회).

수집 결과는 `data` 브랜치에 커밋 1개로 올라갑니다.

| 파일 | 내용 |
|---|---|
| `snapshot.json` | 최신 1회분(실시간 단계와 12시간 예측, 행사·통제·날씨·도로). 앱이 지도에 씁니다. |
| `history.json` | 시간대별 관측값과 그 시각에 받은 예측값의 누적(45일 보존). |
| `pattern.json` | 요일×시간대 평균 혼잡 단계와 표본 수. |
| `metrics.json` | 예측 일치율(몇 시간 전 예측인지별)과 비교 기준. |
| `briefing.json` | 오늘의 브리핑과 생성·검사 통계. |
| `noise.json` | 장소별 요일×시간대 소음 실측 요약(S-DoT, 7~22시). |
| `noise_state.json` | 센서별 누적 상태(소음 요약을 다시 만들 때 씁니다). |

저장소 Secrets에 `SEOUL_KEY`(서울 열린데이터광장 일반 인증키)와 `GEMINI_KEY`(브리핑용, 없으면 규칙 기반 문장만 사용)가 필요합니다.

## 배포와 감시

| 워크플로 | 하는 일 |
|---|---|
| `collect.yml` | 위의 수집 사슬을 돌리고 결과를 `data` 브랜치에 커밋 1개로 올립니다. |
| `pages.yml` | `main`에 push하면 빌드해서 GitHub Pages에 배포합니다. 빌드 전에 `data` 브랜치의 JSON 5개(`snapshot`, `noise`, `pattern`, `metrics`, `briefing`)를 받아 배포본의 `data-mirror/`에 복사합니다. `data` 브랜치가 없거나 받지 못하면 사본 없이 배포합니다. |
| `watchdog.yml` | 3시간마다 `snapshot.json`의 `updatedAt`을 확인해서 180분을 넘으면 `[watchdog] 수집 정체` 이슈를 한 건 엽니다. 정상으로 돌아오면 댓글을 달고 닫습니다. Actions에서 직접 실행할 때 `stale_minutes`에 0을 넣으면 정상 상태에서도 정체로 판정해 시험할 수 있습니다. |

`data-mirror/`는 같은 출처에서 받는 사본입니다. 앱은 `raw.githubusercontent.com` 요청이 실패한 경우(네트워크 오류, 4xx/5xx, 8초 초과, JSON이 아닌 응답)에만 이 사본을 한 번 읽습니다.

### 서비스 워커 (오프라인 앱 화면)

`public/sw.js`가 앱 화면 파일을 기기에 캐시해서, 연결이 없어도 앱이 열리고 `자료 없음` 또는 `데모 데이터` 배너가 보입니다. `src/sw-register.ts`가 배포본(production)에서만, 페이지 load 뒤에 `BASE_URL/sw.js`를 등록합니다. 새 버전은 안내 없이 설치되어 다음 방문부터 쓰입니다.

- 빌드 뒤 `node scripts/gen_precache.mjs dist`(`pages.yml`에 단계가 있습니다)가 `dist/sw.js`의 자리표시를 채웁니다. 미리 받는 목록은 `index.html`, `manifest.webmanifest`, 아이콘, 해시가 붙은 `assets/*`(필수)와 `data/snapshot-demo.json`, `data/cards.json`, `data/card_modules.json`, `samples/*.wav`(받지 못해도 설치를 막지 않음)입니다. 캐시 이름에는 이 목록의 이름과 내용에서 만든 빌드 해시가 들어가고, 새 워커가 켜질 때 옛 캐시를 지웁니다. 로컬에서 `npm run build`만 하면 자리표시가 비어 있어 미리 받기 없이 방문한 파일만 캐시하므로, 오프라인 시험은 `gen_precache`까지 실행한 `dist`로 합니다.
- 해시가 붙은 `assets/*`와 `samples/*`는 캐시를 먼저 쓰고, `index.html`과 `manifest.webmanifest`, `data/*`는 네트워크를 먼저 받아 보고 안 될 때 캐시를 씁니다.
- 지도 타일, `raw.githubusercontent.com`, `data-mirror/`, `models/`(자체 호스팅 소리 분류 모델), TF Hub(Kaggle, Google Cloud Storage) 요청은 서비스 워커가 응답하지 않고 브라우저가 그대로 처리합니다. 소리 분류 모델은 앱이 IndexedDB에 저장합니다.

### 소리 분류 모델 (자체 호스팅)

`public/models/yamnet/`에 YAMNet(TensorFlow.js graph-model)의 `model.json`과 샤드 4개(합계 16,038,316바이트)를 수정 없이 넣었고, 배포하면 `https://zaczam98-art.github.io/calm-map/models/yamnet/model.json`으로 열립니다. 출처(TF Hub `google/tfjs-model/yamnet/tfjs/1`), 파일별 SHA-256, 라이선스(Apache-2.0)와 확인한 근거 주소는 `public/models/yamnet/NOTICE.md`에 있습니다.

- 모델이 저장되어 있지 않은 기기에서 처음 측정할 때 `src/lib/sound.ts`가 앱과 같은 출처의 이 파일(요청 5건)을 먼저 받습니다. 받지 못하면(404, 차단, JSON이 아닌 응답) 기존 TF Hub 주소(Kaggle과 Google Cloud Storage로 넘어갑니다)로 한 번 더 시도합니다. 받은 모델은 IndexedDB(`calm-yamnet`)에 저장해서 다음 방문부터 다시 받지 않고, 진행률 표시와 무응답 45초 끊기도 두 경로에 똑같이 적용됩니다.
- 서비스 워커는 `models/` 요청에 응답하지 않고 `scripts/gen_precache.mjs`도 이 폴더를 미리 받기 목록에서 뺍니다. IndexedDB 저장본과 서비스 워커 캐시에 같은 16MB가 두 벌 쌓이지 않게 하기 위해서입니다.
- 저장소 크기: 바이너리 약 16MB(15.3MiB)가 git 이력에 한 번 들어갑니다. 파일을 바꾸지 않으면 더 늘지 않고, 배포 산출물 `dist`와 새로 clone하는 크기는 그만큼 커집니다.
- Node 평가: `YAMNET_LOCAL=public/models/yamnet/model.json`을 주고 `scripts/eval_sound.ts`를 실행하면 TF Hub 대신 이 파일을 읽습니다. 환경변수가 없으면 이전처럼 TF Hub에서 받습니다.

## 투표 기간 운영 규칙

투표 기간에는 배포를 하루 한 번 이하로 묶어서 하고, 긴급 수정만 예외로 합니다. main에 push할 때마다 `pages.yml`이 돌아 해시가 붙은 JS 파일 이름이 바뀌는데, `index.html`은 최대 10분 동안 캐시되어 이전 `index.html`을 가진 방문자가 삭제된 JS를 요청할 수 있기 때문입니다. 투표를 시작하기 전에는 게시 주소(https://zaczam98-art.github.io/calm-map/)에서 부하 시험을 한 번 하고, 첫 화면이 뜨는 시간과 실패 건수를 "측정 결과"에 적습니다. 수집 정체는 `watchdog.yml`이 3시간마다 `snapshot.json`의 `updatedAt`을 확인해서 180분을 넘으면 `[watchdog] 수집 정체: 마지막 갱신 …` 이슈를 한 건 여는 방식으로 알립니다. 투표 기간에는 하루 한 번 저장소 Issues에서 열린 watchdog 이슈가 있는지 확인하고, 있으면 Actions의 `collect-seoul-citydata`를 Run workflow로 실행합니다(정상으로 돌아오면 다음 점검에서 이슈가 자동으로 닫힙니다). 메일 알림을 받으려면 저장소의 Watch 설정에서 Issues를 켜야 하고, Issues 기능이 꺼져 있으면 watchdog이 실패합니다. 배포할 때마다 `data` 브랜치의 `snapshot.json`, `noise.json`, `pattern.json`, `metrics.json`, `briefing.json`이 `data-mirror/`에 복사되며, 앱은 raw.githubusercontent.com 요청이 실패한 경우에만 이 사본을 한 번 읽습니다. 사본은 마지막 배포 시점의 자료라서 오래될 수 있고, 그때도 화면의 갱신 시각 경고는 그대로 작동합니다.

## 지수 산식 (가설 v1.1)

지수는 0~100이고 낮을수록 무던합니다. 장소와 시간대마다 혼잡 점수 C, 소음 점수 N, 소리 점수 S를 차례로 합치며, 전체 식은 정보 화면 맨 아래의 "자세한 계산 방법과 검증 기록"과 `src/lib/index.ts`에 있습니다. 이 절은 혼잡 점수 C의 비교 범위를 설명합니다.

- C는 서울시 혼잡도 단계의 기준값(여유 15, 보통 40, 약간 붐빔 65, 붐빔 90)에서 시작해, 같은 단계 안에서 예상 인구 중앙값의 위치로 ±10점을 보정한 값입니다. C = 기준값 + (위치 - 0.5) × 20이고, 위치는 (그 칸의 인구 중앙값 - 범위의 최솟값) / (범위의 최댓값 - 범위의 최솟값)을 0~1로 제한한 값입니다.
- 비교 범위는 스냅샷에 담긴 12시간 예측 전체입니다(실시간 관측값이 있으면 함께 넣습니다). 지금 시각으로 자르지 않기 때문에, 같은 스냅샷으로 계산하는 동안에는 정각이 지나도 같은 칸의 C와 지수가 바뀌지 않습니다. 새 스냅샷을 받으면 범위가 바뀌므로 값도 바뀝니다.
- 변경 이유와 전후 수치는 `docs/eval/index_v1_1_window.md`에 있습니다. 정각 전후 안정성은 `node scripts/recommend_check.mjs <snapshot.json>`의 [4]가 확인합니다.

무던한 곳 안내는 직선 거리만 쓰고 이동 시간은 계산하지 않습니다. 직선 3km를 넘는 후보에 붙이는 표지는 이동 부담을 재서 정한 값이 아니라 경험으로 정한 기준입니다. 현재 규칙(더 무던한 단계부터, 같은 단계 안에서는 가까운 순)으로 고른 후보 11,850건 중 72.4%가 직선 3km 안이었습니다(2026-10-08부터 5일 시험, 소음을 더한 지수).
카드가 시트에서 고른 시각의 예측으로 후보를 고르는 것은 시트와 카드가 같은 시각을 기준으로 하게 하려는 방식입니다. 이 방식을 지금 관측으로 후보를 고르는 방식과 비교했습니다. 기준 장소와 시각의 쌍마다 후보가 도착 시각 관측에서 기준 장소보다 단계가 낮았는지 세어 비율을 구했습니다. 예측으로 고른 후보의 비율은 2시간 뒤 76.8%로 지금 관측으로 고른 후보의 69.0%보다 높았고, 차이의 95% 구간은 6.1~9.3%p입니다(2,674쌍). 3시간 뒤는 71.8% 대 62.4%에 차이의 95% 구간 7.8~10.9%p(2,756쌍), 6시간 뒤는 63.2% 대 48.4%에 12.4~17.4%p(1,404쌍)이며, 세 시차 모두 구간의 하한이 0을 넘었습니다. 지금 관측으로 고른 후보가 1, 2, 3시간 뒤에도 그 시각의 기준 장소보다 단계가 낮았던 비율은 76.7%, 65.7%, 56.9%입니다(3,810쌍, 3,528쌍, 3,162쌍).
구간은 기준 장소 121곳 단위로 다시 뽑는 부트스트랩(1,000회)으로 구했고, 같은 장소의 이어진 시각이 겹치는 영향은 반영하지 못해서 실제보다 좁습니다. 끝값은 무작위 추출에서 나오므로 시드를 바꿔 다시 뽑으면 끝값의 소수 첫째 자리가 최대 2만큼 달라졌고(시드 네 개로 확인), 하한이 0을 넘는 결과는 모두 같았습니다. 비율은 `src/data/nearbyEvidence.json`에 소수 여섯째 자리까지 저장하고, 이 문서의 퍼센트 수치는 그 저장값을 소수 첫째 자리까지 한 번만 반올림한 값입니다.
시험 수치는 2026-10-08부터 5일 자료이며 같은 장소의 이어진 시각이 겹쳐 있어 실제 오차는 더 큽니다. 시험한 지수에는 소리 측정과 아이 맞춤을 넣지 않았고(기기 안에만 있는 자료입니다), 서울시 예측은 시차 2, 3, 6, 12시간의 중앙값만으로 다시 만들었습니다(앱은 서울시가 주는 12시간 예측을 모두 씁니다). 그래서 소리 측정이나 아이 맞춤을 켠 지수에는 이 수치를 적용할 수 없습니다. 후보가 아이에게 더 편한지는 재지 않았습니다. 또한 기준 장소가 외출 시간(8시부터 21시) 관측에서 이미 보통 이상이던 쌍만 시험했으므로, 그 밖의 상황에는 이 수치를 적용할 수 없습니다.
