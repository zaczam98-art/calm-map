# 지수 산식 v1.1: 혼잡 점수 C의 비교 범위 변경 기록

이번 변경은 단계 기준값(15, 40, 65, 90), ±10 보정 폭, 소음·소리 식, 단계 경계(35, 65)를 그대로 두고, 혼잡 점수 C가 같은 단계 안에서 위치를 재는 비교 범위만 바꿉니다. 산식 표기는 가설 v1에서 가설 v1.1이 됩니다.

- 수정 전 기준 커밋: 8f9f4f2 (`src/lib/index.ts`)
- 수정 후: 작업 트리의 `src/lib/index.ts` (`congestScore`, `hourScores`)
- 사용한 스냅샷: 서울시 실제 자료, 수집 시각 2026-10-09 08:06(`updatedAt`), 121곳, 실시간 관측 07:35 또는 07:40, 예측 12칸(09:00~20:00)
- 소음 자료: 2026-09-05부터 2026-10-08까지 29일 치, 115곳(나머지 6곳은 소음 없이 C만 씁니다)

## 변경 이유

설계 정의는 "혼잡 점수 C = 단계 기준값 + 그 장소의 12시간 예측 안에서 인구가 많은 편인지 적은 편인지에 따른 ±10 보정"입니다. 그런데 수정 전 구현은 비교 범위를 "지금 시각부터 남은 칸"으로 잡았습니다. 자료는 그대로인데 정각이 지나면 범위에서 지난 칸이 빠지고, 같은 칸의 위치와 지수가 달라졌습니다. 라이브 점검에서 확인한 현상이고, 이 문서의 시험으로 수치를 재었습니다.

## 전후 식

공통: 칸 p의 인구 중앙값 m(p) = (min + max) / 2, 단계 기준값 base(p) = 여유 15 / 보통 40 / 약간 붐빔 65 / 붐빔 90, 범위 W에서 lo = min m, hi = max m.

| | 식 |
|---|---|
| 수정 전 (v1) | C = clamp(base + (pos - 0.5) × 20, 0, 100), pos = (m(p) - lo) / (hi - lo), W = 지금 시각(정시 t) 이후 칸 |
| 수정 후 (v1.1) | C = clamp(base + (pos - 0.5) × 20, 0, 100), pos = clamp((m(p) - lo) / (hi - lo), 0, 1), W = 스냅샷의 예측 칸 전체 |

- 수정 전 W는 실시간 관측(`live`)과 예측(`fcst`)에서 시각이 t 이후인 칸만 모으고, 시각이 같은 칸은 하나만 남깁니다. t가 한 시간 지날 때마다 맨 앞 칸이 빠집니다. 마지막 칸 하나만 남으면 hi <= lo여서 C는 base가 됩니다.
- 수정 후 W는 `live`(있으면)와 `fcst` 전체이고 t와 무관합니다. 현재 코드가 `live`를 범위에 넣던 의미를 그대로 둔 것입니다. 지금 칸을 비워 두고 1~2시간 안의 관측으로 대신 채운 칸도 같은 `live` 값이므로 항상 범위 안에 있습니다.
- pos의 0~1 제한은 비교 대상 칸이 범위 밖에 있을 때도 보정이 ±10을 넘지 않게 하는 안전장치입니다. 현재 호출 경로에서는 칸이 항상 범위 안이라 결과가 바뀌지 않습니다. `scripts/recommend_check.mjs`의 경계값 시험이 범위 밖 입력에서 30과 50이 나오는지 확인합니다.
- `hourScores`의 반환 구조, `parts`(c, n, s, w, offset, base), `scoreAt`, `recommend`의 계약은 그대로입니다.

예: 미아사거리역 16시 칸(보통, 인구 중앙값 9,250)은 07시에 보면 지수 48이고, 시간이 지나 11시 47, 12시 46, 13시 43, 14시와 15시 40으로 내려오다가 16시에 보면 30(무던함)이 됩니다. 16시 이후 칸이 모두 9,250 이상이라 위치가 0이 되기 때문입니다. v1.1에서는 같은 칸이 어느 시각에 봐도 48(보통)입니다. 범위가 관측 4,250부터 예측 9,750까지이고 위치가 약 0.91이기 때문입니다.

## 영향

조건은 소리 표본과 맞춤이 없는 기본 상태입니다. "혼잡만"은 지수가 C를 반올림한 값이고, "소음 포함"은 실제 소음 자료를 써서 지수 = 0.6 × C + 0.4 × N을 반올림한 값입니다. 보는 시각 t는 07시부터 20시까지 정시마다 계산했고, 예측 12칸(121곳, 1,452칸)만 셉니다. 한 칸은 자기 시각 이전의 t에서만 보이므로 비교 쌍은 장소 × 칸 × 보는 시각으로 12,342개입니다. 차이는 v1.1 지수에서 v1 지수를 뺀 값의 절대값입니다.

### 정각 전후 안정성

## 범위와 한계

- 스냅샷 한 장(2026-10-09 08:06), 하루 치 예측으로 잰 값입니다. 다른 날에는 분포가 다릅니다. 수치는 변경이 일으키는 변동의 크기를 보여 주는 것이고, 지수가 더 정확해졌다는 근거는 아닙니다.
- v1.1은 범위가 스냅샷에 고정되므로 새 스냅샷을 받으면 범위가 바뀌므로 같은 칸의 값도 바뀝니다. 바뀌는 시점이 정각이 아니라 자료를 새로 받는 때입니다.
- 범위에 `live`를 넣는 것은 이전 코드의 의미를 유지한 선택입니다. 이 스냅샷에서는 121곳 중 63곳의 `live` 관측이 예측 12칸의 인구 범위 밖에 있습니다(61곳은 예측 최솟값보다 낮고, 2곳은 최댓값보다 높습니다). `live`를 빼고 예측만으로 범위를 잡으면 예측 1,452칸 가운데 438칸(30.2%)의 지수(혼잡만)가 달라지고, 평균 0.94점, 최대 10점 차이가 나며, 20칸은 3단계가 바뀝니다. `live`를 넣을지 뺄지는 아직 검증하지 않았습니다.
- 수집이 오래 끊겨 `live`가 몇 시간 전 값이어도 범위에는 그대로 들어갑니다. 이 경우를 따로 다루지 않습니다.
- 지수 산식 전체는 여전히 검증 전 가설입니다. 이번 변경은 시각에 따라 값이 흔들리는 구현 결함을 정의에 맞게 고친 것입니다.
