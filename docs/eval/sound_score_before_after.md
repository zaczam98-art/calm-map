# 소리 점수 S 수정 전후 기록

이번 변경은 값을 조정한 것이 아니라 식에 있던 구조 결함 두 가지(분모, 민감도 상쇄)를 제거한 것입니다. 태그 가중(돌발음 1.0, 군중 0.7, 기계·차량 0.5, 음악·안내방송 0.5, 말소리 0.3, 배경 0.1), 소리와 기본 지수를 섞는 비중 w = min(0.5, n/(n+6)), 혼잡 단계 기준값(15, 40, 65, 90), 단계 경계(35, 65)는 수정 전과 같습니다. 시험 스크립트가 두 버전의 태그 가중이 같은지 확인하고, 다르면 실행을 멈춥니다. FABLE_결정 3번이 가설로 남기라고 한 기준값, 경계, 소리 가중 상한 0.5를 건드리지 않았으므로 그 결정과 충돌하지 않습니다.

- 수정 전 기준 커밋: f765233 (`src/lib/index.ts`)
- 수정 후: 작업 트리의 `src/lib/index.ts`
- 재현: 저장소 루트에서 `node scripts/sound_score_test.ts` (약 5초, 결과를 `docs/eval/sound_score_before_after.json`에 씁니다)

## 결함 두 가지

| | 식 |
|---|---|
| 수정 전 | S = clamp(1.4 × 100 × Σ(w_t·s_t·v_t) / Σ(w_t·s_t), 0, 100) |
| 수정 후 | S = clamp(100 × Σ(v_t·w_t·s_t), 0, 100) |

v_t는 태그 t의 (확률×강도) 평균, w_t는 태그 가중, s_t는 맞춤을 켰을 때의 태그 민감도(꺼져 있으면 1)입니다.

1. 분모가 값이 0인 태그까지 키웁니다. 앱이 만드는 소리 버킷은 여섯 태그가 모두 숫자이고 없는 소리는 0입니다(`summarize`와 `mergeBucket`이 그렇게 만듭니다). 그래서 맞춤을 끄면 분모는 항상 w의 합 3.1이고, 돌발음 1.0만 잡힌 세션도 S는 140/3.1 = 45.2에서 멈춥니다.
2. 민감도 s_t가 분자와 분모에 함께 들어갑니다. 민감도를 올리면 그 태그의 값 v_t가 가중평균에서 차지하는 비중만 커지므로, v_t가 평균보다 낮은 태그의 민감도를 올리면 S가 오히려 내려갑니다. 값이 0인 태그의 민감도를 바꿔도 분모가 바뀌어 S가 달라집니다.

수정 전 식의 상수 1.4는 가중평균이 0.3~0.6에 몰려서 늘려 둔 배율이었습니다. 분모를 없애면 이 배율이 필요 없으므로 함께 없앴습니다.

심사위원 A가 재현한 "민감도를 올리면 S가 내려간다"는 현상은 수정 전 식에서만 나타나고, 수정 후 식에서는 나타나지 않습니다(아래 P4).

## 속성 시험

무작위 시험은 시드 20261009로 고정한 2,000개 입력입니다. 수정 전 식의 실패는 결함을 보여 주는 기록이며 종료 코드에 넣지 않습니다.

| 번호 | 성질 | 수정 후 | 수정 전 |
|---|---|---|---|
| P1 | 돌발음 1.0뿐인 세션은 S가 90 이상 | 통과 (S=100) | 실패 (S=45.2) |
| P2 | 배경음 1.0뿐인 세션은 S가 10 이하 | 통과 (S=10) | 통과 (S=4.5) |
| P3 | 태그 값이 커지면 S는 줄지 않음 | 통과 (위반 0/2000) | 통과 (위반 0/2000) |
| P4 | 세션에 있는 태그의 민감도를 올리면 S는 줄지 않음 | 통과 (위반 0/2000) | 실패 (위반 972/2000) |
| P5a | 키가 없는 태그의 민감도는 S에 영향 없음 | 통과 (위반 0/2000) | 통과 (위반 0/2000) |
| P5b | 값이 0인 태그의 민감도는 S에 영향 없음 | 통과 (위반 0/2000) | 실패 (위반 1983/2000) |
| P6 | 모든 태그가 0이면 S는 0 | 통과 | 통과 |
| P7 | n=0이거나 버킷이 없으면 null | 통과 | 통과 |
| P8 | 맞춤을 끄면 민감도와 무관하고 민감도 1과 같음 | 통과 (위반 0/2000) | 통과 (위반 0/2000) |
| P9 | S는 항상 0 이상 100 이하 | 통과 (위반 0/2000) | 통과 (위반 0/2000) |

P4의 고정 예시는 돌발음 0.2, 군중 0.8인 세션에서 돌발음 민감도를 0.5, 1, 1.5로 올리는 경우입니다. 수정 후 S는 66, 76, 86으로 오르고, 수정 전 S는 35.5, 34.3, 33.4로 내려갑니다.

P5a는 수정 전 식에서도 통과합니다. 수정 전 식이 값 0과 키 없음을 다르게 다루기 때문이고, 앱이 만드는 입력은 P5b 쪽입니다.

## 사이렌 비슷한 세션의 지수 전후

세션은 돌발음 0.72(나머지 태그 0), 30창입니다. 소리 비중은 w = min(0.5, 30/36) = 0.5이고, 지수는 (1 − w) × 기본 지수 + w × S를 반올림한 값입니다. 장소는 혼잡 예측 단계만 있는 단일 시각이며 기본 지수는 단계 기준값 15, 40, 65, 90입니다. 표의 값은 `hourScores`를 수정 전과 수정 후 코드로 각각 호출해 얻었고, 반올림 전 값을 같은 식으로 직접 계산한 검산과 일치했습니다.

맞춤을 끈 경우:

| 장소 | 소리 없음 | 수정 전 (S 32.5) | 수정 후 (S 72) |
|---|---|---|---|
| 여유 | 15 | 24 | 44 (무던함에서 보통으로) |
| 보통 | 40 | 36 | 56 |
| 약간 붐빔 | 65 | 49 | 69 (붐빔) |
| 붐빔 | 90 | 61 | 81 |

수정 전 식에서는 사이렌이 잡힌 세션이 보통, 약간 붐빔, 붐빔 장소의 지수를 모두 내렸습니다(40에서 36, 65에서 49, 90에서 61). 수정 후에는 여유, 보통, 약간 붐빔 장소가 모두 소리 없음보다 오릅니다.

돌발음 민감도를 1.5로 켠 경우(수정 후 S 100, 수정 전 S 42):

| 장소 | 소리 없음 | 수정 전 | 수정 후 |
|---|---|---|---|
| 여유 | 15 | 29 | 58 |
| 보통 | 40 | 41 | 70 |
| 약간 붐빔 | 65 | 54 | 83 |
| 붐빔 | 90 | 66 | 95 |

수정 전 식에서는 민감도를 1.5로 올려도 약간 붐빔 장소의 지수가 54로 소리 없음(65)보다 낮습니다.

## ESC-50 태그별 S 분포

`docs/eval/esc50_result.json`의 `perClip`에는 정답 태그와 예측 태그만 있고 태그별 확률(`scores`)이 없습니다. 확률은 YAMNet 모델을 다시 돌려야 얻을 수 있어서 실측 S 분포는 계산하지 못했습니다. 이 단계에서는 모델을 내려받지 않았습니다. `scripts/eval_sound.ts`가 `perClip`에 `scores`를 남기도록 고쳐 다시 평가하면, 시험 스크립트가 같은 JSON에 실측 분포(`esc50.measured`)를 자동으로 채웁니다.

대신 모델 없이 얻을 수 있는 값만 썼습니다. 로컬 ESC-50 음원 920개(5창씩)에서 앱과 같은 방식으로 창 강도(dBFS −60~−10을 0~1로)를 구했고, 태그 확률은 가정값 p로 두었습니다. 계산한 세션은 정답 태그 하나만 값이 있고(v = p × 창 강도 평균) 나머지 태그는 0입니다. 다른 태그가 함께 잡히면 수정 후 S는 이보다 더 오릅니다.

창 강도 실측(0~100으로 환산):

| 태그 | 음원 수 | 중앙값 | 10%~90% | 50 이상 비율 |
|---|---|---|---|---|
| 돌발음 | 360 | 72.0 | 23.1~93.6 | 76.1% |
| 배경 | 200 | 73.3 | 40.1~85.2 | 85.5% |
| 기계·차량 | 240 | 84.8 | 62.1~96.9 | 97.5% |
| 군중 | 80 | 66.8 | 40.7~88.5 | 81.3% |
| 음악·안내방송 | 40 | 81.4 | 68.5~94.8 | 97.5% |

가정한 p에 따른 S의 중앙값과 50 이상 비율(수정 후 / 수정 전):

| 태그 | p=0.5 | p=0.8 | p=1.0 |
|---|---|---|---|
| 돌발음 | 36.0, 4.2% / 16.3, 0% | 57.6, 65.8% / 26.0, 0% | 72.0, 76.1% / 32.5, 0% |
| 군중 | 23.4, 0% / 10.6, 0% | 37.4, 8.8% / 16.9, 0% | 46.8, 48.8% / 21.1, 0% |
| 기계·차량 | 21.2, 0% / 9.6, 0% | 33.9, 0% / 15.3, 0% | 42.4, 2.5% / 19.1, 0% |
| 음악·안내방송 | 20.4, 0% / 9.2, 0% | 32.6, 0% / 14.7, 0% | 40.7, 0% / 18.4, 0% |
| 배경 | 3.7, 0% / 1.7, 0% | 5.9, 0% / 2.6, 0% | 7.3, 0% / 3.3, 0% |

- 맞춤을 끈 수정 전 식은 단일 태그 세션에서 어떤 p로도 S가 45.2를 넘지 못해 50 이상 비율이 모든 칸에서 0%입니다.
- 수정 후 식에서 돌발음 S가 100에 닿으려면 p × 강도 평균이 1이어야 합니다. p=1을 가정해도 90분위가 93.6이어서 100에 붙지 않습니다.
- 배경음은 p=1에서도 S의 최댓값이 10이고 중앙값은 7.3이어서 지수를 크게 올리지 못합니다(P2).

## 한계

- 소리가 100 근처에 붙는 것이 과한지는 판단하지 못했습니다. 판단에는 돌발음 360개의 실측 확률이 필요하고, 위 표는 p를 가정한 값이라 돌발음 50 이상 비율이 4.2%에서 76.1%까지 가정에 따라 움직입니다. 경계값과 상수는 바꾸지 않았습니다.
- 소리와 기본 지수는 가중평균으로 섞입니다. S가 기본 지수보다 낮으면 지수가 내려갑니다. 위 표에서 붐빔(90) 장소에 사이렌 세션을 섞으면 81로 내려가는 것이 그 예이며, 이번 수정 범위 밖이어서 바꾸지 않았습니다.
- 소리 측정이 없는 시간대는 S가 null이어서 지수가 달라지지 않습니다(P7).
- 수정 후 식도 검증 전 가설입니다. 이번 시험이 보이는 것은 식의 구조(분모 제거, 민감도 상쇄 제거)이고, 가족이 느끼는 소리 부담과의 일치는 따로 검증하지 않았습니다.
- 이 기록을 쓴 시점에 `src/components/Info.tsx` 46행은 수정 전 식("가중평균에 1.4를 곱해")을 설명하고 있습니다. 코드 주석(`src/lib/index.ts` 31~36행)의 식과 맞추려면 Info.tsx 문장을 고쳐야 합니다.
